# Data Card: zhtw-pii synthetic test set

## Summary

`data/testset/v0/test.jsonl` is a fully synthetic Traditional Chinese
dataset for evaluating PII and sensitive-entity detection. It contains no
real individuals, addresses, or organizations. Every row is generated by
`zhtw_pii/data/generate.py` from public statistical lexicons recombined by
hand-written sentence templates.

## Generation method

- **Entities**: PERSON (person names, including honorific forms such as
  "王先生"), ADDRESS (Taiwan-style addresses, city down to district or
  full street), and ORG (organization names built from a generic prefix
  and a legal-entity suffix).
- **Sources**: surnames from a public household-registration frequency
  list (`zhtw_pii/data/lexicon/surnames.txt`); given names from a small
  table of common name characters, combined at random; cities and
  districts from a small public list; organization names from generic
  synthetic prefixes plus common legal suffixes (limited liability
  company, clinic, law firm, studio, foundation, association).
- **Templates**: 17 sentence templates across 6 scenarios (customer
  service, admin, finance, medical scheduling, recruiting, logistics).
  Template IDs are retained per row (`template_id`) for auditing.
- **Noise transforms**: fullwidth/halfwidth digit and punctuation
  conversion, removal of spaces and punctuation, and honorific-suffix
  variation, applied with tier-dependent probability. See
  `docs/adr/0003-fully-synthetic-data.md` for why this approach was
  chosen over using real text.
- **Determinism**: a single `random.Random(seed)` instance drives every
  draw; the same seed always produces byte-identical JSONL output (see
  `tests/test_generate.py`).

## Tiers (v0, 300 rows)

| Tier | Definition | Rows |
|---|---|---|
| easy | single entity, no noise | 80 |
| medium | 2 to 3 entities, light noise | 100 |
| hard | heavy noise: stripped punctuation, honorifics, fullwidth digits, partial addresses | 70 |
| negative | no PII, number-dense (order numbers, dates, amounts) | 50 |

## Known biases and limitations (Day 0)

- **Surname and given-name distribution is narrow.** The lexicon covers
  about 40 surnames and 41 given-name characters; real Taiwanese names
  draw from a much larger character set and regional variation this
  generator does not model.
- **Address coverage is 8 cities with 2 to 4 districts each**, not the
  full set of Taiwan administrative divisions, and road names are drawn
  from a 10-entry list of common naming patterns.
- **Organization names are synthetic combinations**, not sampled from any
  real business registry; they are designed to be structurally plausible
  (prefix plus legal suffix) rather than to resemble specific real
  companies.
- **Templates are hand-written, not mined from real documents**, so
  sentence-structure diversity is bounded by the 17 templates in
  `zhtw_pii/data/generate.py`, not by real-world usage.
- **The hard tier does not yet include name-vs-common-word collisions**
  (for example a surname that is also an ordinary adjective), only
  formatting-level noise. This is a known gap against the project's
  hard-tier design goal, tracked internally for v1.
- **One pair of rows is an exact duplicate.** `hard_020` and `hard_052`
  have the same text, entities, tier, and template; the generator happened
  to produce that row twice, and it is the only duplicate among the 300
  rows. All five M1 baselines predict the same spans on both copies, and
  dropping one copy moves any baseline's exact PERSON F1 by at most 0.0020
  and its exact micro F1 by at most 0.0008, without changing the ranking.
  v0 keeps both rows so that published numbers stay reproducible; v1 will
  deduplicate.
- These are exactly why this dataset is a **benchmark for a synthetic
  distribution**, not a claim about real-world accuracy. See the README
  Limitations section.

## Governance

- Only the frozen, versioned test set under `data/testset/v0/` is meant
  to be committed; ad hoc regeneration output elsewhere under
  `data/generated/` is not (see `.gitignore`). Any change to `v0` after
  it is frozen requires a version bump and an entry in
  `data/CHANGELOG.md` (introduced when the set is first frozen, after
  the M1 manual audit below).
- License: the dataset is intended to be released under CC-BY-4.0; the
  code that generates it is MIT, the same as the rest of the repository.
- Manual audit: before v0 is frozen for benchmarking, 30 rows will be
  sampled and manually checked for label correctness (`make
  audit-sample`, an M1 deliverable); results will be recorded in
  `data/testset/v0/AUDIT.md`.
