## Summary

- **S1**: the model file is not the dominant cost on a throttled mobile connection. transformers.js fetches a 22.48 MiB ONNX Runtime WASM binary on every cold visit (about 18 s on emulated 4G). The cold-load target is two numbers (WiFi and 4G); latency is a separate axis, met comfortably by models up to about 17 MiB int8.
- **S2**: tokenization parity between Python and transformers.js is perfect (100 percent `input_ids` agreement, 5 tokenizers, 338 examples). transformers.js exposes **no character offsets**, so the browser reconstructs entity spans from token strings; a prototype does this at 100 percent on the v0 test set for WordPiece backbones.
- **Benchmark**: no locally deployable tool handles Traditional Chinese person names well (best local learned model: Presidio at 0.27 exact F1; GLiNER2-PII does not transfer to zh). A rule baseline reaches 0.66 but with a 32 percent false-positive rate on negatives. A frontier API (Claude Haiku 4.5) reaches 0.85 exact and 1.00 overlap, so the task is easy for a strong model and unsolved locally. **Decision: Path A, train a small model under the S1 size budget, with a layered target (must-have versus regex, stretch versus the API).**

## S1: browser model size budget (Issue #1)

Method: Playwright headless Chromium, mobile emulation (390x844, DPR 3, mobile UA), CDP network throttling. Conditions: `desktop-unthrottled`; `mobile-4g` (10 Mbps down, 5 Mbps up, 40 ms RTT); `mobile-fast3g` (1.6 Mbps down, 750 kbps up, 150 ms RTT). Cold load = fresh browser context, no cache, page navigation to pipeline ready. Models served locally to isolate size from CDN variance; one additional run per model against the real HF Hub CDN.

|---|---|---|---|---|---|
| ckiplab/albert-tiny-chinese-ner (exported) | 8.44 MiB | unsupported by transformers.js 4.2.0 | | | |
| ckiplab/bert-tiny-chinese-ner (exported) | 11.11 MiB | 0.32 s | 29.2 s | 180 s | 4.0 / 8.1 ms |
| Xenova/paraphrase-MiniLM-L3-v2 | 16.64 MiB | 0.34 s | 34.0 s | 210 s | 4.3 / 8.8 ms |
| Xenova/bert-base-chinese | 98.80 MiB | 0.63 s | 103.0 s | timeout (90 s cap) | 94.9 / 175.0 ms |
| Xenova/bert-base-multilingual-cased-ner-hrl | 170.23 MiB | 0.72 s | 165.0 s | timeout (90 s cap) | 58.9 / 129.2 ms |

Desktop and mobile-4g rows are medians of 3 cold runs. Real HF Hub CDN loads, unthrottled (about 11.6 MB/s): 3.96 s (MiniLM-L3), 8.88 s (bert-base-chinese), 13.49 s (mBERT NER).

Without COOP/COEP headers there is no `SharedArrayBuffer`, so ONNX Runtime Web falls back to `ort-wasm-simd-threaded.asyncify.wasm` (22.48 MiB, single threaded), fetched before the model. Measured cold loads match "runtime bytes plus model bytes over bandwidth". The `optimum-cli export onnx` plus dynamic int8 path works for `ckiplab/bert-tiny-chinese-ner` and loads in transformers.js; ALBERT exports but is unsupported by transformers.js 4.2.0.

### Findings

1. **Locally deployable learned tools are weak on Traditional Chinese.** GLiNER2-PII's model card lists en/fr/es/de/it/pt/nl; on zh it scores 0.60 exact micro F1 on the easy tier and collapses to 0.03 on hard. Presidio's spaCy zh NER finds city-level GPE, not street addresses.
2. **The regex baseline is a lower bound with an unusable false-positive rate.** 16 of 50 negatives are flagged, all from the same token (`金額` read as surname plus given name). A guardrail that fires on a third of clean inputs is a guardrail people turn off.
3. **ADDRESS F1 of 1.000 for regex is a test-set artifact.** `data/generate.py` builds every address from one template (county, district, road, number); regex hits it on every tier. The column cannot discriminate any tool's real address quality until test set v1 (#15) adds non-templated addresses. ORG at 1.000 for Haiku suggests the same for that column.
4. **A frontier API finds essentially everything.** Haiku's overlap F1 is 1.000 on all three entities with zero false positives on negatives. Its exact PERSON F1 of 0.8529 (203 tp, 35 fp, 35 fn) breaks down as 33 cases of honorific convention (gold includes 小姐 / 先生 / 女士 as instructed; the model omitted them despite the instruction) and 2 genuine segmentation ambiguities (劉文 / 劉文投遞, 蘇淑 / 蘇淑安排). The exact-plus-overlap pair already exposes this; no new metric is needed, but the explanation belongs in `docs/benchmark.md`, not only in a PR thread.
5. **Adapter lesson: never ask a language model for character offsets.** The first Haiku run used a schema of `start` / `end` integers; only 179 of 439 overlapping spans matched exactly, with start positions shifted left by 1 in 93 cases, by 2 in 35, down to 6. The model had found the entities (overlap 0.97 to 0.99); the indices were miscounted. The adapter now asks for verbatim entity strings and locates them in code (`str.find` with a forward cursor; unlocated items are counted, never guessed). The rerun reports 0 unlocated, 0 relocated, 0 ignored, 0 parse failures. Two of the four human-written few-shot examples had wrong offsets as well; a regression test now pins them.
6. Model id `claude-haiku-4-5` (undated) resolved on the first real call in both runs. Cost of one 300-example run: about USD 0.11 (estimated from bytes sent).

## Path decision (final, 2026-09-14)

**Path A: train a small model for accuracy, under the S1 size budget.** Path B's compression step is subsumed because the student is trained at BERT-tiny scale directly. The stop condition is not met: no locally deployable system reaches 0.90, and the one system above 0.85 is an API that cannot satisfy G3 (in-browser execution, no data egress) regardless of its score.

Acceptance for M3 on the frozen v0 test set, 3 seeds (42/43/44), every seed:

| Level | PERSON exact F1 | ORG exact F1 | FPR on negatives | Size | Statistics |
|---|---|---|---|---|---|
| **Must** | >= 0.75 (regex 0.6617 plus 5pp with margin) | >= 0.56 | <= 0.05 | int8 <= 15 MiB | McNemar p < 0.05 versus regex, all seeds |
| **Stretch** | >= 0.90 (Haiku 0.8529 plus 5pp) and overlap >= 0.98 | | | | reported, not required |

ADDRESS is not scored for the decision until test set v1 (#15).

**Caveat stated up front.** Training data and the test set come from the same generator (disjoint templates, shared lexicon and structure). Meeting the stretch target on v0 is therefore a floor, not a victory over the API; the README says so, and the claim is retested on v1 with non-templated, free-form data before it is made in public.

## Risk register updates

- **R2** rewritten: no browser-side offsets; client-side reconstruction required; UTF-16 indexing hazard. Mitigations known (S2).
- **R3** confirmed by data: the ADDRESS column is saturated by a trivial regex on every tier. v1 test set (#15) is the mitigation; until then the column is reported but not scored.
- **R4** confirmed and quantified: the WASM runtime, not the model, binds on 4G.
- New: LLM adapters must use surface-text location (finding 5). Encoded as a rule in the engineering guidelines.
- New: `npm audit` reports 4 high-severity advisories in transitive dependencies of `@huggingface/transformers`; review before M2 ships a page that loads ONNX.

## Guidance for M2 and M3

- M2 skeleton weights: `ckiplab/bert-tiny-chinese-ner` exported and quantized as in S1 (label schema differs; map or ignore for the skeleton).
- Span reconstruction: port `spikes/s2_tokenizer_parity/scripts/reconstruct_offsets.py`, iterating code points.
- M3 training target: BERT-tiny architecture with the bert-base-chinese vocabulary; report exact and overlap, per entity, per tier, plus FPR; compare against regex (must) and Haiku (stretch) as above.
- Honorific convention: keep the v0 convention (honorific inside the PERSON span) and state it in the data card; a coverage-style metric is optional for v1.

## Process lessons

1. **Parallel agents must not share one checkout.** Now a pre-spawn checklist rule; reviewers use a detached worktree.
2. **Stop the original agent before spawning a replacement.** An agent that ended its turn with a background process running resumes when the process ends. On 2026-09-10 a presumed-idle agent woke and pushed superseded results while a replacement was working in the same checkout. Rule: stop, confirm no processes, then respawn.
3. **Local environments do not belong in an iCloud-synced tree.** A torch virtualenv plus two `node_modules` trees inside the synced `~/Documents` produced a file-provider and Spotlight storm (load 12.5, git commands hung for minutes). Mitigation in place: `*.nosync` mirrors with symlinks and `.metadata_never_index`; a permanent move is a pending workspace decision.
4. **Pins drift; resolve, do not assume.** transformers.js 4.2.0, `optimum-onnx`, `huggingface_hub < 1.0`.
5. **Timeouts must include every byte on the critical path** (runtime plus model), and **workflow files must run once for real** (a YAML step name containing `: ` parsed as a mapping; `actionlint` did not catch it).
6. **Do not ask a language model to count characters** (finding 5).
